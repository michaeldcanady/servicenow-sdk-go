# CI stores no long-lived secrets, except listed exceptions that expire

<!-- Keywords MUST, MUST NOT, SHOULD, SHOULD NOT, MAY are interpreted per RFC 2119 / RFC 8174 (https://www.rfc-editor.org/rfc/rfc2119). -->
<!-- Add the Jira webhook secret's name to the allowlist in Verify when ADR 024 exception 2 takes effect. -->

MUST: Authenticate CI with `GITHUB_TOKEN`, OIDC, or GitHub's built-in approval for bot-PR runs.
MUST: Add a row to the exceptions table in ADR 024, with an owner and an expiry date, in the same PR that adds a `secrets.*` reference.
MUST NOT: Add a GitHub App private key, a personal access token, or an octo-sts trust policy without a new ADR.
SHOULD: Grant each job the least `permissions:` it needs.
MAY: Start `PR Gate` with `workflow_dispatch` from the release workflow, after a scratch PR shows that the dispatched run satisfies the required check.

## Verify

```bash
# Fails when a workflow or action reads a secret that isn't GITHUB_TOKEN or a listed exception.
! grep -RhoE 'secrets\.[A-Za-z0-9_]+' .github/workflows .github/actions \
  | sort -u \
  | grep -vE '^secrets\.(GITHUB_TOKEN|SN_INSTANCE|SN_USERNAME|SN_PASSWORD|SN_CLIENT_ID|SN_CLIENT_SECRET)$'
```

## Rationale

A stored secret stays valid until someone rotates it, and any workflow change can leak it. See [ADR 024](../../website/docs/contributing/adrs/024-no-long-lived-ci-secrets.md).
