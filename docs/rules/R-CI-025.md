# Three required checks gate every merge

<!-- Keywords MUST, MUST NOT, SHOULD, SHOULD NOT, MAY are interpreted per RFC 2119 / RFC 8174 (https://www.rfc-editor.org/rfc/rfc2119). -->
<!-- Rulesets live as code in NerdIT-Tech/infra-terraform. Verify reads the live ruleset because this repo can't see that source. -->

MUST: Require exactly `PR Gate`, `PR Policy`, and `CodeQL` on the `main` and `release/v*` rulesets.
MUST: Name the gate job `PR Gate` as a plain top-level job, not a reusable-workflow call.
MUST NOT: Put a workflow-level `paths:` filter on the workflow that defines `PR Gate`.
MUST: Turn every gate check on when change detection fails.
MUST: Keep strict status checks on.
MUST NOT: Require an approving review.
MUST NOT: Let an agent push to or approve a PR in CI.
MUST: Log each admin-bypass merge on the release-branch-protection page.
SHOULD: Put a new content check in `PR Gate` and a new metadata check in `PR Policy`, not in a new required check.

## Verify

```bash
# Requires an authenticated `gh`. Fails when the live required checks on main differ from the three.
want='["CodeQL","PR Gate","PR Policy"]'
got="$(gh api repos/michaeldcanady/servicenow-sdk-go/rules/branches/main \
  --jq '[.[] | select(.type == "required_status_checks") | .parameters.required_status_checks[].context] | sort')"
[ "$got" = "$want" ]
```

## Rationale

One stable set of check names lets the gate change without a ruleset change, and the bypass log records where the guarantee didn't hold. See [ADR 025](../../website/docs/contributing/adrs/025-delivery-system-boundary-and-merge-gate.md).
