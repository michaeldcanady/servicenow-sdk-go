# Build a query

Compose a ServiceNow encoded query from typed conditions and use it to
filter a table request.

:::note
Condition values are written into the encoded query verbatim, and ServiceNow's
encoded-query syntax has no way to escape its structural characters (`^`
separates clauses, `,` separates list values, `@` separates pairs). A value
containing one of them — for example, text taken from user input — could
otherwise append arbitrary clauses and widen or alter your query, so the
builder rejects such values at construction time instead.

Always check `Error()` on the finished condition before serializing or
sending it:

```go
q := query.And(
    query.Boolean("active").Is(true),
    query.String("name").Is(userInput), // rejected if userInput contains ^ , or @
)
if err := q.Error(); err != nil {
    // The value was rejected — do not serialize or send this condition.
    return err
}
sysparmQuery := q.String()
```

A condition that reports an error has no valid encoded-query form. If you
serialize one anyway, `String()` renders `<invalid query>` in place of the
rejected part — an intentionally unusable term, never a silently weakened
query. The same validation covers caller-supplied fragments of date-time
composites (`Javascript()`, `JS()`, and `OnSpecialty()`).
:::

## When to use this pattern

- You're filtering records with more than one or two conditions, or building
  queries from runtime values
- You want the compiler to catch operator/type mismatches instead of
  discovering a malformed encoded query at runtime
- For a short, static filter, passing the encoded-query string directly (as
  in [List and query records](tables/list-and-query-records.mdx)) is fine —
  the builder earns its keep when composing conditions by hand gets
  error-prone

## Required values

| Value      | Description                                    |
| ---------- | ---------------------------------------------- |
| Table name | The table to filter (for example, `incident`)  |
| Conditions | The fields, operators, and values to filter by |

### Field types and operators

Conditions start from a typed field constructor — `query.String`,
`query.Number`, `query.Boolean`, `query.Date`/`query.DateTime` — each
exposing the operators valid for that type (`Is`, `Contains`, `IsOneOf`,
`Before`, …). Combine conditions with `.And(...)`/`.Or(...)` or the
top-level `query.And(...)`/`query.Or(...)`.

## Tips

- Encoded-query cheat sheet: `^` joins with AND, `^OR` with OR, `LIKE`
  matches substrings — the builder emits these for you.
- The same encoded string works anywhere a `sysparm_query` is accepted (for
  example, [filtering attachments](attachments/download-record-attachments.mdx)).
