# Credentials rebuild

The credentials rebuild replaces the old per-flow credential types with a
single provider surface: every flow returns an
`authentication.AuthenticationProvider`, and `NewExternalOIDCProvider` adds
support for third-party OpenID Connect (OIDC) identity providers.

The rebuild ships **additively** in the v2 module. Your existing code keeps
compiling: the v2 constructors, types, and options stay in place, marked
deprecated. New code should use the per-flow option structs. The deprecated
symbols are scheduled for removal in the next major release, and the module
path stays `github.com/michaeldcanady/servicenow-sdk-go/v2`.

## What changed

| Area | Keep using (deprecated) | Recommended |
| ---- | ----------------------- | ----------- |
| Construction options | Functional options: `WithInstance`, `WithURL`, `WithAllowedHosts`, `WithTokenStore`, `WithHTTPClient`, `WithScopes`, `WithPort`, `WithStateGenerator`, `WithURLOpener`, `WithServerFactory` | Per-flow option structs (`ClientCredentialsOptions`, `ROPCOptions`, `AuthorizationCodeOptions`, and others) embedding `CommonOptions` |
| Instance URL | Set on the provider with `WithInstance` or `WithURL` | Set once on the client with `WithInstance` |
| Credential types | `ClientCredentialsCredential`, `ROPCCredential`, `JWTCredential`, `AuthorizationCodeCredential`, `BaseAccessTokenProvider` | The `AuthenticationProvider` returned by the `New*Provider` constructors |
| `Authority` | `Authority`, `NewInstanceAuthority`, `NewCustomAuthority`, `TokenURL`, `AuthURL`, `RevocationURL` | The client's instance configuration |
| Token store | `TokenStore` (keyed by client ID), `SetTokenStore` | `KeyedTokenStore` (keyed by `TokenKey{Authority, ClientID}`) |
| Errors | `CredentialError`, `Oauth2Error`, `NewOauth2Error`, `NewCredentialError`, `ErrEmpty*` sentinels | The shared sentinels in the `errors` package |

Both surfaces travel through the same constructors. `AuthOption` is now an
interface, satisfied by the deprecated `WithX` helpers and by the new option
structs, so a constructor accepts either call style:

```go
// Deprecated, still compiles.
cred, err := credentials.NewClientCredentialsProvider(
    "client-id", "client-secret",
    credentials.WithInstance("myinstance"),
    credentials.WithScopes("useraccount"),
)

// Recommended.
cred, err := credentials.NewClientCredentialsProvider(
    "client-id", "client-secret",
    credentials.ClientCredentialsOptions{
        CommonOptions: credentials.CommonOptions{
            Scopes: []string{"useraccount"},
        },
    },
)
```

One source-compatibility note: `AuthOption` is an interface now, not a
function type. A bare `credentials.AuthOption(func(*credentials.AuthConfig) {})`
literal no longer compiles. Use one of the `WithX` helpers or an option struct
instead.

## Constructors

| Constructor | Options |
| ----------- | ------- |
| `NewClientCredentialsProvider(clientID, clientSecret, opts ...AuthOption)` | `ClientCredentialsOptions` |
| `NewROPCProvider(clientID, clientSecret, username, password, opts ...AuthOption)` | `ROPCOptions` |
| `NewJWTProvider(clientID, clientSecret, tokenProvider, opts ...AuthOption)` | `JWTOptions` |
| `NewAuthorizationCodeProvider(clientID, clientSecret, opts ...AuthOption)` | `AuthorizationCodeOptions` |
| `NewPrivateAuthorizationCodeProvider(clientID, clientSecret, opts ...AuthOption)` | `AuthorizationCodeOptions` |
| `NewPublicAuthorizationCodeProvider(clientID, opts ...AuthOption)` | `AuthorizationCodeOptions` |
| `NewExternalOIDCProvider(clientID, opts ExternalOIDCOptions)` | `ExternalOIDCOptions` |
| `NewBasicProvider(username, password, opts ...BasicOptions)` | `BasicOptions` |
| `NewBearerTokenAuthenticationProvider(tokenProvider, opts ...BearerOptions)` | `BearerOptions` |

## Set the instance once

The client owns the instance URL and the allowed hosts. Pass the provider to
the client, then give the client the instance URL a single time:

```go
cred, err := credentials.NewClientCredentialsProvider(
    "client-id", "client-secret",
    credentials.ClientCredentialsOptions{},
)
if err != nil {
    log.Fatal(err)
}

client, err := servicenowsdkgo.NewServiceNowServiceClient(
    servicenowsdkgo.WithAuthenticationProvider(cred),
    servicenowsdkgo.WithInstance("https://myinstance.service-now.com"),
)
```

The deprecated path sets the instance on the provider itself and still works:

```go
cred, err := credentials.NewClientCredentialsProvider(
    "client-id", "client-secret",
    credentials.WithInstance("myinstance"),
)
```

## Authorization code

Private clients carry a client secret; public clients do not and use PKCE
with `S256` automatically.

```go
// Private: confidential client with a secret.
cred, err := credentials.NewPrivateAuthorizationCodeProvider(
    "client-id", "client-secret",
    credentials.AuthorizationCodeOptions{
        CommonOptions: credentials.CommonOptions{
            AllowedHosts: []string{"myinstance.service-now.com"},
        },
        Port:          5001,
        StateGenerator: customStateGenerator,
        URLOpener:     customOpener,
        ServerFactory: customServerFactory,
    },
)

// Public: no secret.
cred, err := credentials.NewPublicAuthorizationCodeProvider(
    "client-id",
    credentials.AuthorizationCodeOptions{},
)
```

## ROPC

ROPC is discouraged for new integrations because it handles user credentials
directly. It is **not** deprecated: the flow keeps working, and the
discouragement lives in the package documentation and in the
[ROPC authentication guide](authentication/ropc.mdx). Prefer authorization
code with PKCE or client credentials.

The rebuild adds fail-fast validation: an empty username or password returns
`ErrEmptyUsername` or `ErrEmptyPassword` at construction instead of failing
later mid-request.

```go
cred, err := credentials.NewROPCProvider(
    "client-id", "client-secret", "username", "password",
    credentials.ROPCOptions{
        CommonOptions: credentials.CommonOptions{
            AllowedHosts: []string{"myinstance.service-now.com"},
        },
    },
)
```

## External OIDC

External OIDC is new. It discovers the identity provider's endpoints, runs the
authorization code with PKCE flow against the provider, and presents the
resulting token to ServiceNow. See the
[external OIDC guide](authentication/external-oidc.mdx) for the full setup.

```go
cred, err := credentials.NewExternalOIDCProvider(
    "client-id",
    credentials.ExternalOIDCOptions{
        CommonOptions: credentials.CommonOptions{
            AllowedHosts: []string{"myinstance.service-now.com"},
            Scopes:       []string{"openid", "profile", "email"},
        },
        Issuer:      "https://login.microsoftonline.com/{tenant}/v2.0",
        TokenSource: credentials.ExternalOIDCTokenSourceIDToken,
    },
)
```

## Token store

The recommended store, `KeyedTokenStore`, keys tokens by authority and client
ID so tokens for two instances or two registrations never collide:

```go
type MyTokenStore struct{}

func (s *MyTokenStore) Save(ctx context.Context, key credentials.TokenKey, token *credentials.AccessToken) error {
    return nil
}

func (s *MyTokenStore) Load(ctx context.Context, key credentials.TokenKey) (*credentials.AccessToken, error) {
    return nil, nil
}

func (s *MyTokenStore) Delete(ctx context.Context, key credentials.TokenKey) error {
    return nil
}
```

```go
type TokenKey struct {
    Authority string // instance URL or OIDC issuer
    ClientID  string // OAuth client ID
}
```

The deprecated `TokenStore` interface keys tokens by client ID alone. It still
works: the provider adapts it to a `KeyedTokenStore` by using the key's client
ID. Migrate to `KeyedTokenStore` to keep tokens for different instances apart.

## Errors

Check errors against the shared sentinels in the `errors` package:

```go
import snerrors "github.com/michaeldcanady/servicenow-sdk-go/v2/errors"

err := ...
if errors.Is(err, snerrors.ErrEmptyClientID) {
    // handle a missing client ID
}
```

The deprecated `credentials.ErrEmpty*` sentinels hold the same values, so
`errors.Is` matches across both names. `CredentialError` and `Oauth2Error`
remain for code that references them.

## Deprecation policy

- Nothing is removed in v2. Every deprecated symbol keeps working.
- Removing the deprecated surface is a breaking change, so it waits for the
  next major release.
- The module path stays `.../v2`. There is no v3 module to migrate to.

## Verification

After you adopt the new surface, confirm that:

1. Provider construction uses the per-flow option structs.
2. The instance URL is set exactly once, on the client.
3. New token store implementations use `KeyedTokenStore` and `TokenKey`.
4. ROPC construction validates an empty username and password.
