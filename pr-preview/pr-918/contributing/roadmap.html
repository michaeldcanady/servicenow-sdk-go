Roadmap from v2 to v3

This page describes where the SDK and its repository are headed and the order of work to get there. It also defines the scope of v3.0.0.

The roadmap breaks the work into units. A unit is one small pull request (one concern, ideally under about 300 changed lines) or one non-code action, such as a settings change. Each unit becomes its own issue when work on it starts. Issue and pull request numbers on this page refer to the servicenow-sdk-go issue tracker.

Where the repository is today​

An audit in November 2026 found that the code is healthy and the process around it isn't:

  • The build, golangci-lint, unit tests, and mocked integration tests all pass. Most packages have 85–99% statement coverage. The exception is caseapi, at 60%.
  • Since August 2026, the history shows 169 chore commits, 29 fix commits, and 4 feat commits. Most of that effort went into CI.
  • Merges need an admin bypass because two required status check names no longer match the names that the workflows report (#917).
  • Documentation Stable, Sync Project Status, and the Dependabot Go updates fail on main.
  • The domain-first design in ADRs 017–021 is still Proposed, and the pull requests that carry the planned credentials and logging work (#872 and #690) have stalled.
  • Agent configuration is spread across .agents/, .claude/, .opencode/, docs/agents/, docs/rules/, and two near-identical instruction files.

Where the repository is going​

  1. v2.x is stable and acts as the bridge. Each new surface ships next to the surface it replaces, and the old surface is marked deprecated.
  2. v3.0.0 is the domain-first SDK. The new surfaces are the only surfaces, the deprecated code is gone, and the module path ends in /v3.
  3. CI stays green by default. Every workflow has a stated purpose and a recent passing run. Required check names are treated as a contract.
  4. Agent configuration is vendor-neutral and has one source.
  5. Documentation follows one style, and Vale enforces it.

Guardrails​

These rules apply to every unit:

  • Required check names are a contract. If a pull request renames a job or moves it into a reusable workflow, update .github/policies/servicenow-sdk-go-branch-protection.yml in the same pull request.
  • Consult the ADRs first. If a change contradicts an ADR, amend the ADR in the same pull request.
  • Preserve error identity in v2. When a package-local sentinel is replaced by a shared one, keep the old name as a deprecated alias so that errors.Is still matches. New error categories keep errors.As with *core.ServiceNowError working.
  • Hold the v3 release pull request. After the /v3 module-path change lands, release-please proposes 3.0.0 right away. Don't merge that pull request until every v3 unit is done.

Critical path​

The credentials rebuild is the longest chain of dependent units. Its design is already accepted in ADR 015, so it starts as soon as Phase 0 is done and runs in parallel with Phases 1 and 2:

P0-15 → P3-24 through P3-39 → P3-59 and P3-60 → P3-65 (v2.2.0) → P4-01 → P4-02 → P4-07 → P4-10 through P4-13 → P4-18 → P4-21 (v3.0.0)

Step 0 comes first. It's short, and the tasks it adds are how you verify every later unit before you push.

These tracks run in parallel with the credentials chain:

  • The Phase 0 tracks, after the merge gate is fixed (P0-06).
  • The Phase 1 removals.
  • The Phase 2 chain P2-01 → P2-04 → P2-05 → P3-01, which gates the table work.
  • Logging, caseapi coverage, and the spike on the sentinel for unexpected response types.

Phase 5 is off the critical path.

Work units​

Size key:

  • XS: a few lines.
  • S: under about 300 changed lines.
  • M: the largest allowed size.

Units marked Action are non-code steps. A unit with "new" in the Issue column gets a new issue when work starts.

Step 0: Local tooling with mise​

Goal: mise replaces just as the task runner and pins every tool that CI uses. You can run each CI check that has a local equivalent before you push, with the same tool versions that CI uses. Every later phase uses these tasks to verify its units.

Phase 4: v3.0.0​

Scope of v3.0.0​

  • Table2() becomes Table(). The legacy Table(name string) and Table2() are both removed (ADR 018).
  • Typed tables and the exported foundation are the default documented path (ADR 017 and ADR 019).
  • The credentials package exposes only providers, options, TokenStore, and sentinels, and the v1 adapter is removed (ADR 015).
  • Categorized errors are the default error mapping (ADR 021).
  • Every symbol marked Deprecated: is removed.
  • The module path ends in /v3.

Exit checks​

Each code unit passes these checks before it merges:

  • mise run check passes locally. Until Step 0 is done, run go build ./..., go test ./..., go test -tags integration ./tests/integration/..., and golangci-lint run ./... directly.
  • New exported API has table-driven tests.
  • Documentation changes pass Vale.

Each phase is done when its checks pass:

  • Step 0:

    • On a fresh devcontainer, mise install installs every pinned tool.
    • mise run check passes on main.
    • Each just recipe has a mise task that does the same thing.
    • The justfile is gone, and no page or instruction file mentions just.
    • CI and mise.toml pin the same tool versions.

  • Phase 0:

    • A pull request merges without an admin bypass.
    • CI, Documentation Stable, CodeQL, and zizmor are green on main.
    • The Dependabot pull requests merge.
    • v2.1.1 and its security advisory are published.

  • Phase 1:

    • The workflow directory matches the workflow inventory page.
    • Every remaining workflow is green or passes a manual dry run.
    • zizmor reports no findings.

  • Phase 2:

    • The shim script produces no diff in CI.
    • AGENTS.md and .agents/ name no vendor outside the shim notes.
    • Local agents and OpenCode Review read the same agent definitions.

  • Phase 3:

    • Every replaced surface carries a Deprecated: notice.
    • The integration and nightly end-to-end runs cover Table2, typed tables, and the new credential providers.

  • Phase 4:

    • A sample consumer module builds against /v3.
    • No Go file contains Deprecated:.
    • A backport pull request to the v2 maintenance branch merges.

  • Phase 5:

    • No workflow references a local reusable workflow or composite action.
    • The required checks report under their expected names.
    • CI stays green for a week.
